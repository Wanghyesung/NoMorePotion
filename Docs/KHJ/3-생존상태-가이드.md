# 3. 생존 상태 (SurviveStatus) 가이드

코드 위치: `Assets/KHJ/Script/SurviveStatus/` / 구간표 데이터: `Assets/Resources/ScriptableObjects/Config/SurviveStatusEffectTable.asset`

## 한 줄 요약
체온, 정신력, 수분, 포만감 네 게이지(0~100)가 **구간(상태)** 으로 환산되고, 구간이 바뀌면 **표(SO)에 적힌 버프/디버프**가 플레이어에게 걸리고 빠진다.

## 구조 한눈에 (화이트보드용)

```
[포션/행동]
    | ChangeStatus(type, amount)
    v
SurviveStatusManager (싱글턴, 허브)
    | Increase*/Decrease*
    v
Body/Mental/Hydration/Satiation Manager --(값 -> 구간 판정)--> "구간이 바뀔 때만" 이벤트
    ^                                                              |
    | ResetAllStatus                                               v
SurviveStatusManager.HandleXxxStateChanged -> SyncEffects(source = 그 게이지 매니저)
    -> SurviveStatusEffectTable.GetEffects(구간) -> BuffContainer.Apply / Remove
```

- 게이지 매니저 4개는 "값 -> 구간"만 안다. 버프가 무엇인지 모른다.
- 어떤 구간에 어떤 효과가 걸리는지는 코드가 아니라 **SurviveStatusEffectTable 에셋(데이터)** 이 안다.
- SurviveStatusManager 는 둘을 잇는 허브다. 이벤트를 구독해 표를 조회하고 BuffContainer 에 건다.

## 핵심 규칙과 이유

**구간 판정**: 높은 쪽은 `>=`, 낮은 쪽은 `<=`. 임계값은 전부 `[SerializeField]` 라서 프리팹 값이 우선이다. (`SurviveStatusManager.prefab` 의 직렬화 값이 코드 기본값과 같음을 확인함)

| 게이지 | 초기값 | 구간 (위에서부터 판정) | 걸리는 효과 (표 기준) |
|---|---|---|---|
| 체온 | 50 | >=70 Hot / <=30 Cold / 그 외 Normal | Hot: 더위(61001), Cold: 추위(61002) |
| 정신력 | 50 | >=90 Smart / <=10 GoToDie / <=30 Confused / <=50 What / 그 외 Normal | Smart: 똑똑이(60001) / Normal: 멍청함(61010) / What: +뭐라고?(61014) / Confused: +혼란(61003) / GoToDie: +죽어라(61009) |
| 수분 | 50 | >=70 Moist / <=0 Dehydrated / <=10 Thirsty / 그 외 Normal | Moist: 촉촉함(60002), Thirsty: 갈증(61004), Dehydrated: 갈증+탈수(61005) |
| 포만감 | 50 | >=90 Full / <=0 Starving / <=20 Hungry / 그 외 Normal | Full: 배부름(61008), Hungry: 허기(61006), Starving: 허기+굶주림(61007) |

(정신력 열의 "+" 는 아래 단계 효과를 누적해서 모두 거는 뜻. 표에 그렇게 적혀 있다.)

왜 이렇게 했나.
- **순서가 중요하다**: 극단값(Smart, GoToDie, Dehydrated, Starving)을 먼저 검사해야 겹치는 범위에서 더 심한 상태가 이긴다. 예) 수분 0 은 `<=10` 도 만족하지만 Dehydrated 가 먼저다.
- **이벤트는 구간이 바뀔 때만**: 값이 매번 변해도 효과 재적용 비용이 안 든다. 대신 "초기 구간 효과"는 이벤트가 안 오므로 `ResetAllStatus` 가 `SyncAllEffects` 를 따로 호출한다.
- **diff 기반 동기화**: `SyncEffects` 는 새 목록에 없는 효과만 빼고, 아직 안 걸린 효과만 건다. 유지되는 효과를 다시 걸지 않으니 **지속/주기 타이머가 초기화되지 않는다**. (예: 정신력 Confused -> What 이 될 때 멍청함은 그대로, 혼란만 빠짐)
- **source = 게이지 매니저**: 효과를 건 주체를 구분해서, 체온 구간 변경이 포션이나 다른 게이지가 건 효과를 건드리지 않는다.
- **정신력 90 이상 = 똑똑이, 미만 = 멍청함(제작 실패 50%)** 은 코드가 아니라 **표 데이터**다. 정신력 매니저는 Smart/Normal 구간만 알려주고, 제작은 걸린 효과에서 `GetCraftFailChance()` 로 읽는다. 기획이 바뀌면 에셋만 고친다.
- 주의: 초기값이 50 이고 판정이 `<=50` 이므로 시작 직후 정신력은 **What(뭐라고? + 멍청함)** 상태다. (코드 기준 도출, Play 모드 확인은 하지 못함)

## 팀원이 쓰는 법 (검증된 public API)

| 이름 | 용도 |
|---|---|
| `SurviveStatusManager.Instance` | 싱글턴. null 체크 후 사용 |
| `ChangeStatus(SurviveStatusType type, int amount)` | 양수 증가, 음수 감소, 0 은 무시. 0~100 이라 퍼센트와 수치가 같음 |
| `ResetAllStatus()` | 네 게이지 초기화 + 구간 효과 재동기화 (Start 에서 자동 호출) |
| `PlayerBuffContainer` | 내 플레이어의 BuffContainer (포션 폭발에서 "내 플레이어인지" 판정, 제작 실패 확률 조회) |
| `BindPlayer(GameObject player)` | 컨테이너 Owner 연결. 로컬 플레이어 생성 후 호출 |
| 각 매니저 `Increase*/Decrease*(int amount)` | amount 는 양수. 0~100 으로 clamp 후 구간 재판정 |
| `OnBodyTemperatureStateChanged`, `OnMentalStateChanged`, `OnHydrationStateChanged`, `OnSatiationStateChanged` | `Action<Prev, Next>` |
| `MentalStrengthManager.OnDeathThresholdReached` | 정신력 0 이하에서 한 번만 (Reset 하면 다시 가능) |

`SurviveStatusType`: None, BodyTemperature, MentalStrength, Hydration, Satiation.

## 호출 예시

```csharp
// 포션 효과: 수분 +5%  (PotionEffectApplier 와 같은 패턴)
if (SurviveStatusManager.Instance != null)
    SurviveStatusManager.Instance.ChangeStatus(SurviveStatusType.Hydration, 5);

// 정신력 -10 (음수면 내부에서 DecreaseMentalStrength(10) 호출)
SurviveStatusManager.Instance.ChangeStatus(SurviveStatusType.MentalStrength, -10);

// 구간 변화 구독 (구독/해제 대칭)
mentalStrengthManager.OnMentalStateChanged += OnMentalChanged;   // OnEnable
mentalStrengthManager.OnMentalStateChanged -= OnMentalChanged;   // OnDisable
void OnMentalChanged(MentalState prev, MentalState next) { }
```

## 하지 말아야 할 것
- 게이지 값을 직접 대입하지 않는다. 값 setter 는 `private` 이고 증감 메서드로만 바꾼다. (clamp 와 구간 재판정이 거기서 일어남)
- `Increase*/Decrease*` 에 음수를 넘기지 않는다. 방향이 헷갈리면 `ChangeStatus` 를 쓴다.
- 구간 효과를 코드에서 직접 Apply/Remove 하지 않는다. 표(에셋)를 고친다. source 가 달라 diff 동기화와 충돌한다.
- 임계값 필드 이름/타입을 바꾸지 않는다. `[SerializeField]` 라 프리팹 값이 날아간다.
- 코드에 "정신력 90" 같은 숫자를 하드코딩하지 않는다.
- 이벤트 구독만 하고 해제를 빼먹지 않는다.

## 아직 연결 안 된 것
- `BindPlayer` 호출처 없음 (팀원 연결 대기). 연결 전에는 체력 증감 효과(탈수 등)의 대상이 없다.
- `OnDeathThresholdReached` 구독처 없음. 정신력 0 사망 처리는 미연결. (`Player.cs` 에 빈 `OnDeathThresholdReached` 함수만 있고 이벤트에 연결 안 됨)
- 주기 행동 3종은 빈 껍데기: `StopPlayerMove`(추위), `ConsumeFirstInventoryItem`(허기, 항상 false 반환), `DrinkHeldPotion`(갈증).
- 시간 경과 자동 감소(5초당 1% 등), 체온 지대, 밝기별 정신력 변화는 TODO 주석 상태.

## 용어집
- **정신력**: 정신 게이지 (발표 자료에 섞여 나오는 "지능" 과 같은 것)
- **구간(State)**: 게이지 값을 임계값으로 나눈 단계 enum
- **표(SurviveStatusEffectTable)**: 구간 -> 효과 목록을 담은 ScriptableObject
- **source**: 효과를 건 주체. 여기서는 각 게이지 매니저
- **BuffContainer**: 버프/디버프 목록과 타이머를 관리하는 컴포넌트
- **diff 동기화**: 바뀐 부분만 빼고 거는 방식
