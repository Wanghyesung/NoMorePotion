# 2. 상태 효과 퀴즈 (12문항)

> 코드 근거: `Assets/KHJ/Script/StatusEffect/` (`BuffContainer.cs`, `ActiveStatusEffect.cs`, `StatusEffectData.cs`, 모듈들). 계산 문제는 모두 `BuffContainer` 의 실제 로직(곱연산, 버프 ×1.7 상한, 디버프 ×0.2 하한) 기준이며, 별 말이 없으면 같은 스탯(MoveSpeed) 하나만 본다.

## A. 객관식

**Q1.** 같은 포션(같은 source)을 다시 던졌을 때 **새로 넘긴 percent 는 무시되고 지속시간만 원래대로 돌아가는** 정책은?
1) Unique  2) RefreshDuration  3) Stackable  4) None

**Q2.** 디버프 "탈수"(체력 증감 300, 1초마다, `Stackable`)가 서로 다른 source 2건 걸려 있다. 1초당 들어가는 대미지는?
1) 0  2) 300  3) 600  4) 건마다 타이머가 달라 일정하지 않음

**Q3.** 이동속도 버프 +40%, +30%, +50% 가 `Stackable` 로 각각 걸려 있고 디버프는 없다. `GetStatMultiplier(StatType.MoveSpeed)` 는?
1) 2.73  2) 2.2  3) 1.7  4) 1.2

**Q4.** `Unique` 정책 효과를 `Apply(data, new object())` 로 호출한다(매번 새 source). 올바른 설명은?
1) 항상 두 번째부터 false 를 반환한다
2) 매번 새 건이 추가된다. 스탯은 가장 강한 한 건만 반영되지만 목록은 계속 늘어난다
3) 예외가 발생한다
4) `RefreshDuration` 처럼 지속시간이 갱신된다

## 정답 및 해설

**Q1. 2) RefreshDuration.** `Apply` 의 `RefreshDuration` 분기는 `FindSame`(같은 data + 같은 source)을 찾으면 `same.RefreshDuration()` 만 호출하고 `true` 반환. 새 건이 안 만들어지므로 새 percent 가 들어갈 곳이 없다. 이유: 수치를 올려 재투척하는 악용 방지. (`BuffContainer.Apply`, `ActiveStatusEffect.RefreshDuration`)

**Q2. 2) 300.** 틱은 정책과 무관하게 `IsStrongest` 인 한 건만 발동. Stackable 이어도 동일. 체력 증감은 `GetStrength` 가 전부 0 이라 먼저 걸린 건이 담당. (`ProcessTickModules`, `IsStrongest`)

**Q3. 3) 1.7.** 1.4×1.3×1.5 = 2.73 이지만 버프 곱 상한 `1 + MaxBuffPercent/100 = 1.7` 로 `Mathf.Min`. (`RecalculateStatMultipliers`)

**Q4. 2).** `FindSame` 은 `Equals(source)` 로 비교하므로 매번 다른 source 는 "다른 주체"가 되어 Unique 가 막지 못한다. 목록은 늘고, 스탯/틱은 `IsStrongest` 로 한 건만. 교훈: source 는 안정적인 동일 객체여야 한다.

**Q5.** 정답: **t=3: 0.85, t=7: 0.65, t=12: 0.5.**
- t=3: 버프 1.4×1.3=1.82 → 상한 1.7. 디버프 `Unique` 단일 건 0.5. 1.7×0.5 = 0.85.
- t=7: 5초 효과 만료 → 버프 1.3. 1.3×0.5 = 0.65.
- t=12: 10초 효과도 만료 → 버프 1.0. 디버프 0.5 → 0.5.
상한을 먼저 씌우고 곱한다는 점이 포인트. (`RecalculateStatMultipliers`, 만료 시 `RemoveAt` 이 dirty 표시)

**Q6.** **0.7.** 실제 적용 수치는 20, 30(override 0 이라 SO 값 -30 사용), 25. 절댓값 최대 30 인 두 번째 건만 반영 → 1 + (-30/100) = 0.7. 함정: override 0 을 "0%"로 비교하면 안 된다. (`GetStrength`, `AccumulateStatMultipliers`)

**Q7.** **0.3.** 디버프: 0.4×0.4×0.4 = 0.064 → 하한 `1 - 80/100 = 0.2` 로 `Mathf.Max` → 0.2. 버프 1.5. 1.5×0.2 = 0.3.

**Q8. 아니다.** `RefreshDuration` 에서 같은 건이 있으면 지속시간만 갱신하고 `true` 를 반환하지만 `OnEffectAdded` 는 발생하지 않는다(새로 목록에 추가될 때만 발생). `true` 의 의미는 "목록에 반영됨(추가 또는 갱신)". (`Apply` 반환 주석, `OnEffectAdded` 주석)

**Q9. 약 1500 (5틱).** source 가 달라 두 건이 공존하지만 틱은 `IsStrongest` 한 건(동률이면 먼저 걸린 A)만 발동하므로 2배가 되지 않는다. 첫 틱은 걸린 직후 다음 Update, 이후 1초마다 → 0, 1, 2, 3, 4초 부근 5회, 5초에 만료 제거가 틱보다 먼저 처리되어 6번째는 없다(프레임 단위 오차는 있을 수 있음). 이유: 중복 대미지 방지. (`ActiveStatusEffect.ConsumeTick`, `TickAndRemoveExpired`)

**Q10.** 반환값 **true**, 배율 **1.4 유지**(새 percent 80 무시, 기존 건에 override 가 0 이라 SO 값 40 사용), `remaining` 은 **원래 duration 10** 으로 리셋되고 새로 넘긴 20초도 무시 → 만료는 **t=16**. 새 건이 안 생기므로 `OnEffectAdded` 도 없다. (`Apply`, `RefreshDuration`: `remaining = duration`)

**Q11. 모범 답안 요지.**
- 버프 폭주(무한 가속)와 디버프 영구 정지를 막는 안전장치이고, 상한 값(+70%, -80%)이 기획 수치로 고정되어 있다(`MaxBuffPercent`, `MaxDebuffPercent`).
- 합친 값에 한 번만 상한을 두면 버프와 디버프가 먼저 상쇄된 뒤에 잘리므로, 예를 들어 버프 ×3 과 디버프 ×0.2 는 0.6 이 되어 "버프가 많이 쌓이면 디버프를 거의 지운다"가 가능해진다. 각각 먼저 상한을 씌우면(1.7, 0.2) 같은 조합이 0.34 로 고정되어 버프를 아무리 쌓아도 디버프를 이기지 못하고, 디버프가 아무리 쌓여도 0.2 아래로는 안 내려가 완전 정지가 되지 않는다.
- 곱연산이라 개별로도 음수 배율이 안 나오고(`Mathf.Max(percent, -100)`), 스탯 종류별로 독립 계산된다.

**Q12. 모범 답안 요지.**
- 한 건만: 같은 효과가 여러 source 에서 걸려도 초당 대미지가 N 배가 되지 않게 하기 위함(정책과 무관, Stackable 포함). 기준은 `IsStrongest`(동률이면 먼저 걸린 건).
- 권한 있을 때만(`HasAuthority`): 멀티플레이(PUN2)에서 모든 클라이언트가 같은 컨테이너를 가지면 각자 대미지를 줘 중복된다. 플레이어는 `photonView.IsMine`, 몬스터는 마스터 클라이언트로 `SetAuthorityCheck` 를 지정하는 구조(현재는 호출처 없음).
- 타이머 같이 소비: 담당 건이 만료/제거되어 순서가 넘어왔을 때 쌓인 틱이 한꺼번에 몰려 들어가지 않도록, 비담당 건도 `ConsumeTick` 을 호출해 타이머를 흘려보낸다. (`ProcessTickModules`)
