# 6. 데이터와 재료 가이드

## 한 줄 요약
기획 구글 시트의 행 하나가 `{ID}.asset` ScriptableObject(SO) 하나가 되고, 런타임은 `PotionDataManager` 가 `Resources` 폴더를 통째로 읽어 ID 로 찾아 쓴다. "기획 시트가 그대로 게임 데이터가 되는 구조"라서, 기획자는 코드 없이 데이터를 늘리고 프로그래머는 ID 만 주고받는다.

## 구조 한눈에
```
구글 시트(원본) → Tools/아이템 데이터 관리자(ItemDatabaseWindow) → Resources/ScriptableObjects/*/{ID}.asset
                                                                   ↓ Resources.LoadAll (Awake)
                                  PotionDataManager (레시피 딕셔너리, ID 딕셔너리, 함정 키워드 목록)
                                                                   ↓
                    InventoryRules.GetMaterialLimit / PotionCrafter / InventoryPacker / TeamInventoryState
```

| 폴더 (Resources/ScriptableObjects) | 타입 | ID 범위 (실제 에셋 기준) | 개수 |
| --- | --- | --- | --- |
| Potions | PotionData | 10001~10033, 11001~11006, 12001~12033 (1만번대) | 72 |
| Materials | MaterialData | 20000~20026 (2만번대) | 27 |
| WorldObjects | WorldObjectData | 30001~34003 (3만번대) | 43 |
| TrapPotionKeywords | TrapPotionKeyword | 50001~50013 (5만번대) | 13 |
| StatusEffects | StatusEffectData | 버프 60001~60007, 디버프 61001~61014 | 21 |
| Config | 설정 SO | PotionExplosionConfig, SurviveStatusEffectTable (ID 없음) | 2 |

공통 인터페이스 `IItemData`: `ID` 프로퍼티 + 에디터 전용 `SetID`. 이것을 구현하면 생성 창의 `CreateButton<T>` 를 재사용할 수 있다.

## 핵심 규칙과 이유
1. **ID 대역으로 종류를 구분한다.** ID 만 봐도 무엇인지 알 수 있어서, 네트워크/인벤토리 패킹처럼 ID(정수)만 오가는 곳이 단순해진다.
2. **SO 는 공유 설정값이다.** 모든 사용처가 같은 SO 를 본다. 남은 횟수, 남은 시간 같은 런타임 변경값은 SO 에 쓰지 않고 별도 클래스/컴포넌트에 둔다. 한 곳에서 바꾸면 전체가 바뀌고 에셋 파일도 오염되기 때문이다.
3. **생성 창은 기존 에셋을 덮어쓰지 않는다.** `CreateAsset` 이 `{ID}.asset` 이 이미 있으면 "생성 실패" 대화상자만 띄우고 끝낸다. 손으로 다듬은 값을 날리지 않기 위해서다. 성공하면 다음 ID(+1)를 자동으로 채운다.
4. **`[SerializeField]` 필드 이름/타입을 바꾸면 저장된 에셋 값이 사라진다.** Unity 는 필드 이름으로 직렬화한다. 그래서 `StackPolicy` 의 `Stackable`(값 3, 구 StrongestWins) 처럼 enum 값도 숫자가 바뀌지 않게 유지한다. 바꾸기 전에 영향받는 에셋을 먼저 확인한다.
5. **레시피 키는 재료 ID 오름차순 쌍이다.** `AddPotionRecipe`/`GetPotionDataFromRecipe` 둘 다 `Math.Min`, `Math.Max` 로 정렬한 `PotionRecipeSet` 을 쓰므로 (A,B) 든 (B,A) 든 같은 포션이 나온다. 조합 타입이 `Material` 이고 재료가 정확히 2개인 포션만 레시피가 된다(아니면 경고).
6. **재료 보관 한도.** `maxHoldCount`: -1 = 기본 한도 99, 0 = 보관 불가, 1~99 = 그 값. 조회 실패(모르는 ID, 매니저 없음)도 99. 개인 인벤토리는 "한 칸 최대 개수", 팀 인벤토리는 "종류별 총량 한도"로 쓴다.
7. **함정 키워드는 포션 SO 와 분리.** 13개(50001~50013)를 `TrapPotionKeywords` 폴더에서 로드하고, 제작 실패 시 `PotionCrafter.PickTrapKeyword` 가 `Random.Range` 로 균등 선택한다. 함정 포션은 원래 포션 + 키워드이므로 포션 ID 를 따로 늘리지 않는다.
8. **중복 매니저는 Awake 에서 자신을 파괴**하고 데이터를 다시 읽지 않는다.

## 팀원이 쓰는 법

### API (grep 으로 확인한 것)
| 호출 | 반환 / 의미 |
| --- | --- |
| `PotionDataManager.Instance.TryGetPotionData(id, out PotionData)` | 포션 ID 조회, 없으면 false |
| `TryGetMaterialData(id, out MaterialData)` | 재료 ID 조회 |
| `TryGetTrapKeyword(id, out TrapPotionKeyword)` | 함정 키워드 ID 조회 |
| `GetPotionDataFromRecipe(firstId, secondId)` | 재료 2개 → 포션, 없으면 null + 경고 (순서 무관) |
| `GetUpgradedPotion(firstPotionId, secondPotionId)` | 같은 포션 2개 → ID+1 포션 (조합 타입이 Potion 일 때만), 아니면 null |
| `TrapKeywords` (`IReadOnlyList<TrapPotionKeyword>`) | 실패 시 뽑을 후보 전체 |
| `PotionDataManager.materialFolderPath / potionFolderPath` | Resources 하위 경로 상수 |
| `InventoryRules.GetMaterialLimit(materialId)` | 재료 보관 한도 (규칙 6) |
| `InventoryRules.DefaultMaterialLimit` | 99 |

### 기획자가 새 데이터를 추가하는 순서 (ItemDatabaseWindow)
1. 메뉴 `Tools/아이템 데이터 관리자` 를 연다.
2. 왼쪽에서 종류를 고른다: Material / Potion / World Object / Buff / Debuff / 함정 키워드 SO 생성.
3. 시작 ID 가 들어가 있다(재료 20001, 포션 10001, 월드 오브젝트 30001, 버프 60001, 디버프 61001, 키워드 50001). 필요하면 대역 안에서 ID 를 직접 고친다.
4. 시트 값(이름, 설명, 아이콘, 효과 등)을 채우고 "생성"을 누른다. 같은 ID 파일이 있으면 실패 알림이 뜬다.
5. 왼쪽 "... 목록"에서 만들어진 에셋을 확인한다. 새 포션은 재료 2개(Material 타입)를 지정해야 레시피로 잡힌다.

## 호출 예시
```csharp
var mgr = PotionDataManager.Instance;
PotionData potion = mgr.GetPotionDataFromRecipe(20003, 20001); // 순서가 바뀌어도 같은 결과
if (potion == null) { /* 레시피 없음 → 제작 실패 처리 */ }

if (mgr.TryGetMaterialData(materialId, out MaterialData mat))
    Debug.Log(mat.materialName);

int limit = InventoryRules.GetMaterialLimit(materialId); // -1 이면 99, 0 이면 보관 불가
```

## 하지 말아야 할 것
- `[SerializeField]` 필드(`_materialID`, `_maxHoldCount` 등) 이름/타입 변경, enum 값 숫자 변경 (저장 데이터 소실).
- ID 대역 위반 (재료를 1만번대로 등). 폴더별로 로드하므로 조회가 어긋난다.
- 같은 ID 중복 생성. 딕셔너리는 마지막에 읽힌 것이 덮어쓴다.
- 런타임에 변하는 값을 SO 에 쓰기 (모든 사용처에 공유됨).
- 레시피 재료를 2개 아닌 개수로 설정하거나, 함정 키워드 SO 를 Potions 폴더에 두기.
- `Assets/Common`, 타 팀원 폴더 임의 수정 (먼저 문의).

## 아직 연결 안 된 것
- `MaterialItem`(월드에 떨어진 재료 + 개수): `Initialize`, `ToSlot` 코드는 있으나 아직 어디에도 연결하지 않았다. 발표 기획상 의도적으로 남긴 코드다.
- 시트에서 SO 로 일괄 생성하는 도구는 이 폴더의 코드에서 찾지 못했다. 현재 창은 한 개씩 생성하는 구조다(일괄 생성은 별도 확인 필요).
- 이 문서는 코드와 에셋 파일명을 읽어 작성했고 Play 모드에서 실제로 실행해 확인하지 않았다.

## 용어집
- **SO(ScriptableObject)**: 씬이 아닌 에셋 파일에 저장되는 데이터 객체.
- **레시피 키**: 오름차순 재료 ID 쌍(`PotionRecipeSet`).
- **함정 키워드**: 제작 실패 시 원래 포션에 덧붙는 효과 SO (13종).
- **maxHoldCount**: 재료 보관 한도 (-1 기본 99, 0 불가).
- **정신력**: 게임 내 수치 이름 (제작 실패 확률에 영향). "지능"이라고 쓰지 않는다.
