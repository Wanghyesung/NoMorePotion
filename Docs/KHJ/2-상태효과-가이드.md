# 2. 상태 효과(버프/디버프) 가이드

## 한 줄 요약
`StatusEffectData`(공유 SO 설정)를 `BuffContainer.Apply` 로 대상에게 걸면 `ActiveStatusEffect`(걸린 상태 한 건)가 생기고, 컨테이너가 중첩 정책·상한·틱을 처리한다. 효과의 내용은 클래스가 아니라 **모듈 조합**으로 표현한다.

## 구조 한눈에 (`Assets/KHJ/Script/StatusEffect/`)
| 파일 | 역할 |
| --- | --- |
| `StatusEffectData.cs` | 설정 SO. `StatusEffectType`(Buff/Debuff), `StackPolicy`, `hasDuration`, `modules` 목록 |
| `StatusEffectModule.cs` | 모듈 부모(추상). 효과가 "하는 일"의 단위 |
| `StatModifierModule.cs` | 스탯 % 보정 (`StatType`: MoveSpeed/AttackPower/Defense/Vision) |
| `HealthChangeModule.cs` | 고정 수치 대미지/회복, 반복 간격(0 = 한 번). 회복은 `IHealable` 필요 |
| `PeriodicActionModule.cs` | 주기 행동 발동 시점만 알림 (`PeriodicActionType`). 행동은 이벤트 받는 쪽이 처리 |
| `CraftFailChanceModule.cs` | 제작 실패 확률(%). 걸린 효과 중 최댓값 사용 |
| `ActiveStatusEffect.cs` | 런타임 한 건: `source`, `percentOverride`, `remaining`, 틱 타이머 |
| `BuffContainer.cs` | 목록 보관, `Apply`/`Remove`, 정책, 상한, 틱, 이벤트 |
| `IHealable.cs` | `Heal(int)` 인터페이스 (`IDamageable` 과 함께 구현) |

## 핵심 규칙과 이유
1. **SO 는 공유, 변하는 값은 `ActiveStatusEffect` 에.** 남은 시간·틱 타이머를 SO 에 쓰면 같은 SO 를 쓰는 모두가 공유해 버린다.
2. **스탯은 곱연산** `1 + percent/100`. 합연산이면 -50% 와 -60% 가 -110% 가 되어 음수 배율이 생기는 문제가 있다. 곱이면 0 아래로 안 간다. (그래도 개별 값은 `-100` 하한)
3. **`StackPolicy`** = `Unique`(1) / `RefreshDuration`(2) / `Stackable`(3, 구 StrongestWins). 에셋에 숫자로 저장되므로 순서 변경 금지.
   - `Unique`: **같은 효과 + 같은 source** 가 이미 있으면 무시(`false`).
   - `RefreshDuration`: 같은 효과 + 같은 source 면 `remaining` 만 원래 duration 으로 되돌림. **새 percent·새 duration 은 무시**. 포션 재투척으로 수치를 올리는 꼼수 방지.
   - `Stackable`: 매번 새 건 추가. 스탯은 전부 곱, 지속시간은 각자.
4. **Unique/Refresh 인데 건이 여러 개일 때**(source 가 다르면 공존): 같은 효과 중 **실제 적용 수치 절댓값**(`percentOverride`, 0 이면 SO 값)이 가장 큰 한 건만 반영, 동률이면 먼저 걸린 것. (`IsStrongest`, `GetStrength`) 이유: 0(=SO 값 사용)인 건을 숫자 0 으로 잘못 비교하지 않기 위해 "실제 값"으로 비교한다.
5. **Stackable 예시(디버프)**: -40% 5초 + -30% 10초 → 0~5초 ×0.6×0.7=0.42, 5~10초 ×0.7. 지속시간이 각자라 먼저 끝난 건만 빠진다. (버프 +40%/+30% 로 같은 구조면 ×1.4×1.3=1.82 이지만 상한 ×1.7 이 먼저 걸려 1.7, 5초 뒤 ×1.3)
6. **상한**: 버프끼리 곱한 값 최대 ×1.7(`MaxBuffPercent`=70), 디버프끼리 곱한 값 최소 ×0.2(`MaxDebuffPercent`=80). **각각 상한을 씌운 뒤 서로 곱한다.** 이유: 버프 폭주/영구 정지 방지, 버프와 디버프가 서로 상쇄될 여지는 남김. 스탯 종류별로 따로 계산.
7. **틱(HealthChange/PeriodicAction)은 정책과 무관하게 한 건만** 발동(가장 강한 건, 동률이면 먼저 걸린 것). 이유: 같은 탈수가 두 건이라 초당 대미지가 2배가 되면 안 된다. 나머지 건도 타이머는 같이 흘려, 담당 건이 사라져도 몰아서 발동하지 않는다.
8. **틱은 권한이 있을 때만** (`HasAuthority`). 멀티플레이에서 모든 클라이언트가 대미지를 주면 중복 대미지가 된다. 확인 함수 미지정이면 항상 true.
9. 첫 틱은 타이머 0 으로 시작해 **걸린 뒤 다음 Update 에** 발동, 이후 interval 마다. interval 0 이면 한 번만. 프레임이 튀어도 한 번 호출에 최대 한 번만 true.
10. 만료 제거 → 틱 순서. 만료된 건은 틱 없이 제거. 시간/틱이 필요한 효과가 없으면 `Update` 를 끈다(`UpdateEnabledState`, 몬스터 다수 대비).

## 팀원이 쓰는 법
| API | 시그니처 | 언제 / 주의 |
| --- | --- | --- |
| `Apply` | `bool Apply(StatusEffectData data, object source, int percentOverride = 0, float duration = 0f)` | 반환 true = 새로 추가 **또는 지속시간 갱신**, false = 무시/실패. `hasDuration` 인데 duration ≤ 0, 타입 None, null 이면 경고 후 false. `percentOverride` 부호 그대로(디버프 음수), 0 이면 SO 값 |
| `Remove` | `int Remove(StatusEffectData data, object source)` | 해당 효과+source 의 모든 건 제거, 제거 개수 반환 |
| `RemoveBySource` | `int RemoveBySource(object source)` | source 가 건 것 전부(버프+디버프). 체온 구간 교체용 |
| `Clear` | `void Clear()` | 전부 제거 (사망 시 등) |
| `Has` | `bool Has(StatusEffectData data)` | 행동 변화만 있는 효과 판정 |
| `GetStatMultiplier` | `float GetStatMultiplier(StatType stat)` | 상한 적용된 최종 배율. 없으면 1. 캐시(목록 변경 시 재계산) |
| `GetCraftFailChance` | `int GetCraftFailChance()` | 버프/디버프 중 최대 실패 확률. 없으면 0 |
| `SetOwner` | `void SetOwner(GameObject owner)` | 플레이어처럼 컨테이너와 주인이 다를 때 호출. `IDamageable` 탐색·`FindByOwner` 등록. 몬스터는 `_assignOwnerOnAwake` 로 자동 |
| `SetAuthorityCheck` | `void SetAuthorityCheck(Func<bool> authorityCheck)` | 예: 플레이어 `() => photonView.IsMine`, 몬스터 마스터 클라 |
| `FindByOwner` | `static BuffContainer FindByOwner(Transform start)` | 맞은 콜라이더에서 부모로 올라가며 컨테이너 탐색. 없으면 null |
| 프로퍼티 | `buffs`, `debuffs`(`IReadOnlyList<ActiveStatusEffect>`), `Owner`, `Damageable`, `HasAuthority` | 읽기 전용 |
| `OnEffectAdded` | `event Action<ActiveStatusEffect>` | 새로 추가될 때만 (갱신/무시는 안 옴) |
| `OnEffectRemoved` | `event Action<ActiveStatusEffect>` | 만료·Remove·Clear 모두 |
| `OnPeriodicAction` | `event Action<ActiveStatusEffect, PeriodicActionModule>` | 권한 있고 담당 건일 때만. 구독/해제 대칭 필수 |

**source 규칙**: `Equals(source)` 로 비교하므로 "같은 주체"는 매번 **같은 객체**여야 한다. 포션은 포션/키워드 SO, 생존 상태는 상태 구간 객체를 쓴다. `new object()` 를 매번 넘기면 Unique/Refresh 가 작동하지 않는다.

## 짧은 호출 예시
```csharp
// 플레이어 연결 (SurviveStatusManager 방식)
buffContainer.SetOwner(player);
buffContainer.SetAuthorityCheck(() => photonView.IsMine);
buffContainer.OnPeriodicAction += HandlePeriodicAction;   // OnDestroy 에서 -=

// 포션: source = 포션 SO, 디버프는 음수 percent
bool applied = container.Apply(statusData, potionSo, -30, 10f);

// 폭발에서 대상 찾기
BuffContainer c = BuffContainer.FindByOwner(collider.transform);

// 체온 구간이 바뀔 때
container.RemoveBySource(oldZone);
```

## 하지 말아야 할 것
- SO(`StatusEffectData`)에 남은 시간·횟수 같은 런타임 값 저장.
- `StackPolicy` enum 순서/값 변경, `StatusEffectData` 의 `[SerializeField]` 필드 이름·타입 변경 (에셋 데이터 유실).
- source 를 매번 새로 만들어 넘기기 / `null` 을 여러 주체가 공유하기.
- 전원이 `HealthChangeModule.Apply` 를 직접 호출 (중복 대미지). 컨테이너 틱 경로를 쓴다.
- `Apply` 반환값을 "새로 걸렸다"로 해석 (Refresh 갱신도 true). 새로 걸렸는지는 `OnEffectAdded`.
- 용어: "지능" 대신 **정신력**.

## 아직 연결 안 된 것
- `GetStatMultiplier` 를 읽는 소비처 없음 (이동속도/공격력 등에 아직 미반영, 에디터 인스펙터 요약에서만 호출).
- 지속 체력 증감 포션의 이후 틱을 맡을 **장판 오브젝트 미구현** (폭발 시 첫 틱만 적용).
- `SetAuthorityCheck` 호출처 없음 (현재 항상 권한 true), `Has`/`Clear`/`RemoveBySource` 는 발표 기획상 의도적으로 남김.

## 용어집
- **source**: 효과를 건 주체 / **percentOverride**: 적용 시점 수치(0 = SO 값) / **Strength**: 비교용 실제 적용 수치 절댓값 / **모듈**: 효과 구성 단위 / **틱**: 반복 발동 시점 / **권한(HasAuthority)**: 이 클라이언트가 틱을 실행해도 되는가
