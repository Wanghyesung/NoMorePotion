# 1. 포션 시스템 가이드

## 1) 한 줄 요약
재료 2개(또는 같은 포션 2개)로 `PotionInstance`를 **제작**하고(정신력이 낮으면 함정 키워드가 붙음), 마시거나 던지면 **그 위치에서 폭발**해 범위 안 모든 대상에게 **효과 목록**을 대상당 한 번씩 적용한다.

## 2) 구조 한눈에
경로: `Assets/KHJ/Script/Potion/` (함정 키워드만 `TrapPotion/`)

| 파일 | 역할 |
| --- | --- |
| `PotionData` (SO) | 포션 정의: ID(1만번대), 타입, 폭발 범위 소/중/대, 조합 타입, 레시피 재료, `effects` 목록 |
| `PotionEffect` + 4종 | 효과 부모 / 상태 효과(`ApplyStatusPotionEffect`) / 체력(`HealthChangePotionEffect`) / 생존 게이지(`GaugeChangePotionEffect`) / 월드 오브젝트 대미지(`WorldObjectDamagePotionEffect`) |
| `PotionInstance` | 제작된 포션 1개(런타임). 원본 `Data` + 함정 키워드 + `InstanceId` |
| `PotionDataManager` | 씬 싱글턴. 포션/재료/키워드를 Resources에서 로드, 레시피 조회 |
| `PotionCrafter` | 정적. 제작 + 실패 판정(함정 키워드 뽑기) |
| `Potion` (MonoBehaviour) | 던져진 포션 오브젝트. 충돌 시 폭발 후 파괴 |
| `PotionExplosion` | 정적. 범위 탐색 + 대상당 1회 적용 |
| `PotionExplosionConfig` (SO) | 소/중/대 반경, 효과가 닿는 레이어 |
| `PotionEffectApplier` | 정적. 대상 1개에 효과 목록 적용 (효과 종류별 분기) |
| `TrapPotionKeyword` (SO) | 함정 키워드(5만번대). 자체 `Effects` 목록을 가짐 |

흐름: `PotionCrafter` -> `PotionInstance` -> (인벤토리) -> `Potion.ExplodeAt` -> `PotionExplosion.Explode` -> `PotionEffectApplier.Apply` (원본, 키워드 순)

## 3) 핵심 규칙과 그 이유
- **마시기 = 던지기와 같은 폭발, 위치만 다름.** 마시기도 플레이어 위치에서 폭발시켜 자신을 포함한 범위 안 전원에게 적용(메모리 규칙). 이유: 효과 적용 경로가 하나라 규칙이 갈라지지 않고, 마시기 전용 코드를 따로 안 만들어도 된다.
- **함정 포션 = 원본 + 키워드.** 새 포션 SO를 만들지 않고 인스턴스에 키워드 하나를 붙인다. 폭발 범위는 원본을 따르고, 효과는 원본 -> 키워드 순으로 둘 다 적용. 이유: 같은 포션이어도 인스턴스마다 함정 여부가 다르므로 SO(공유 데이터)에 둘 수 없고, 포션 수 x 키워드 수만큼 SO가 늘어나는 것도 막는다.
- **실패 판정은 제작 순간.** `Random.Range(0, 100) < 실패확률(0~100 클램프)`. 0이면 항상 성공, 100이면 항상 실패. 확률은 플레이어에게 걸린 상태 효과(똑똑이 0%, 멍청함 50%)에서 읽는다. 정신력 구간 -> 버프/디버프는 `SurviveStatusManager`가 담당(제작은 걸린 효과만 읽음). 이유: 정신력 규칙과 제작 규칙의 결합을 끊는다.
- **키워드는 균등 랜덤.** `TrapKeywords` 풀에서 한 개. 풀이 비면 경고 후 정상 포션으로 제작.
- **폭발 범위 반경은 `PotionExplosionConfig`.** 기본값 소 3 / 중 5 / 대 8m(임시값, 인스펙터 수정). `None`은 소와 같은 반경으로 처리.
- **대상당 한 번.** 콜라이더가 여러 개여도 `BuffContainer` > `IDamageable` > `WorldObject` 우선순위의 키로 중복 제거. 이유: 큰 몬스터가 부위 콜라이더 수만큼 맞는 버그 방지.
- **내 플레이어에게만 생존 게이지 적용.** `GaugeChangePotionEffect`는 `IsLocalPlayer`일 때만. 이유: 생존 상태는 로컬 소유 데이터(다른 플레이어/몬스터엔 없음).
- **첫 틱 규칙.** 지속시간 있는 체력 증감이어도 폭발은 첫 틱(`healthChange.Apply` 1회)만 준다. 이후 틱은 장판 오브젝트(미구현)가 두 번째 틱부터 맡아야 첫 틱과 겹치지 않는다.
- **포션 + 포션 합성.** 같은 포션 2개 -> `ID + 1` 포션, 그 조합 타입이 `Potion`이어야 함(중 = 소+소, 대 = 중+중). 대+대는 `ID+1`이 다른 계열의 소 포션이라 거절된다.
- **레시피는 순서 무관.** 재료 ID를 오름차순으로 정렬한 키로 등록/조회. 조합 타입이 `Material`이고 재료가 정확히 2개인 포션만 등록.
- **충돌 방어.** `Potion.HasExploded`로 중복 폭발 차단, 폭발 버퍼는 64개 고정 재사용(할당 없음, 가득 차면 경고).

## 4) 팀원이 쓰는 법

| 대상 | 시그니처 | 언제 | 주의 |
| --- | --- | --- | --- |
| `PotionCrafter` | `static PotionInstance CraftFromMaterials(int firstMaterialID, int secondMaterialID)` | 재료 2개 제작 | 레시피 없으면 `null`. 인자는 **재료 ID** |
| `PotionCrafter` | `static PotionInstance CraftFromPotion(int firstPotionID, int secondPotionID)` | 포션 2개 합성 | 인자는 **포션 ID**. 불가하면 `null` |
| `PotionCrafter` | `static int GetPlayerCraftFailChance()` | 실패 확률 표시 등 | 컨테이너 없으면 0 |
| `PotionInstance` | `PotionData Data`, `TrapPotionKeyword TrapKeyword`, `bool IsTrap`, `int InstanceId` | 읽기 | `IsTrap`은 실제 값. UI엔 `Inspect` 사용 |
| `PotionInstance` | `bool Inspect(out TrapPotionKeyword trapKeyword)` | R 흔들기 확인 | 조회만 함. 보였다/숨겼다는 호출 쪽(UI) 몫 |
| `PotionInstance` | `bool AssignInstanceId(int instanceId)` | ID 발급 | 이미 있거나 0 이하면 `false`. 발급 권한은 한 곳(마스터) |
| `Potion` | `void Initialize(PotionData)` / `void Initialize(PotionInstance)` | 던질 포션 생성 직후 | 데이터만 주면 정상 포션 취급 |
| `Potion` | `void Explode()` / `void ExplodeAt(Vector3 position)` | 던지기는 충돌 시 자동, 마시기는 플레이어 위치로 `ExplodeAt` | 한 번만 동작, 끝나면 `Destroy` |
| `PotionExplosion` | `static int Explode(PotionData, Vector3)` / `static int Explode(PotionInstance, Vector3)` | 컴포넌트 없이 직접 폭발 | 반환 = 적용된 대상 수. 설정 에셋 없으면 0 |
| `PotionDataManager` | `TryGetPotionData(int, out PotionData)`, `TryGetMaterialData`, `TryGetTrapKeyword` | ID로 복원(네트워크/인벤토리) | 없으면 `false` |
| `PotionDataManager` | `GetPotionDataFromRecipe(int, int)`, `GetUpgradedPotion(int, int)`, `IReadOnlyList<TrapPotionKeyword> TrapKeywords` | 직접 쓰기보다 `PotionCrafter` 경유 | 씬에 매니저 필수 |

## 5) 호출 예시
```csharp
// 제작 (마시기/던지기 전에 인벤토리에 보관)
PotionInstance potion = PotionCrafter.CraftFromMaterials(20001, 20002);
if (potion == null) return; // 레시피 없음

// 흔들기(R 누르는 동안만 UI에 표시)
if (potion.Inspect(out TrapPotionKeyword keyword)) { /* keyword.KeywordName 표시 */ }

// 마시기: 내 위치에서 폭발
var obj = Instantiate(potionPrefab, player.position, Quaternion.identity);
obj.Initialize(potion);
obj.ExplodeAt(player.position);

// 던지기: 프리팹에 Initialize 후 발사 -> 충돌하면 Potion 이 알아서 폭발
```

## 6) 하지 말아야 할 것
- 함정 여부를 SO(`PotionData`)에 넣지 않는다. 인스턴스마다 다르다.
- `PotionInstance.IsTrap`을 플레이어 UI에 바로 노출하지 않는다 (흔들기 연출이 무의미해짐).
- 포션 대미지(`WorldObjectDamagePotionEffect`)를 멀티에서 **전원이 호출**하지 않는다. 폭발을 일으킨 클라이언트 한 곳만(중복 차감, 메모리 규칙).
- `Assets/Common`, 타 팀원 폴더는 먼저 묻고 수정.
- `[SerializeField]` 필드 이름/타입을 바꾸기 전에 영향받는 에셋 확인 (데이터 소실).
- `CraftFromPotion`에 재료 ID, `CraftFromMaterials`에 포션 ID를 넣지 않는다 (ID 체계: 포션 1만 / 재료 2만).
- 지속시간 체력 증감을 폭발에서 반복 적용하려 하지 않는다 (장판 몫).

## 8) 용어집
- **정신력**: 생존 상태 중 하나. 90% 이상 똑똑이(실패 0%), 미만 멍청함(실패 50%).
- **함정 키워드**: 제작 실패 시 붙는 5만번대 SO, 자체 효과 보유.
- **폭발**: 던지기/마시기 공통의 범위 효과 적용 단위.
- **첫 틱**: 지속 체력 증감 중 폭발이 주는 1회분.
- **PotionInstance**: 제작 1회마다 생성되는 런타임 포션(SO 아님).
- **장판**: 지속 대미지용 필드 오브젝트(미구현).
