# 5. 월드 오브젝트 가이드

## 한 줄 요약
씬의 꽃, 나무, 광물 같은 채집물 한 개의 "남은 횟수"를 관리하고, 0 이 되면 재료를 떨어뜨립니다. 멀티플레이에서는 마스터가 검증하고 전원이 같은 횟수를 보도록 동기화합니다.

## 구조 한눈에
| 파일 | 역할 |
| --- | --- |
| `WorldObject` | 씬 오브젝트 1개의 런타임 상태(남은 횟수, 소진 여부, 이벤트) |
| `WorldObjectData` (SO) | 공유 설정(타입, 드롭 타입, 최대 횟수, 드롭 목록). `RollDrops` 로 드롭을 굴림 |
| `MaterialDrop` / `MaterialDropResult` | 드롭 재료 1종의 개수 범위(`Roll`) / 굴린 결과(재료 ID, 개수) |
| `WorldObjectRules` | 차감 규칙 한 곳(`ComputeDecrease`, `ToTargetMask`). 순수 C# |
| `WorldObjectNetState` | 오브젝트들의 횟수 사본. 마스터 검증(`TryValidate`), 전원 적용(`Apply`), 전체 목록(스냅샷) |
| `WorldObjectCommand` / `WorldObjectMessages` | 메시지 구조체 / byte 배열 묶기, 풀기 |
| `WorldObjectNetworkSyncManager` | 씬에 1개. RPC 로 요청 -> 마스터 검증 -> 전원 적용 |
| `WorldObjectNetworkIdTool` | 에디터 메뉴로 네트워크 번호 자동 부여 |
| `WorldObjectDataManager` | ID 로 SO 조회. 월드 오브젝트 재생성 등 나중을 위해 의도적으로 남김 |
| `WorldObjectDamagePotionEffect` | 포션 효과(대상 종류 목록 + 대미지) |

흐름(멀티): `Interact()` -> `InteractAsync` -> 마스터 `RpcRequest` -> `TryValidate` -> `RpcApply`(전원) -> `Apply` -> `ApplyNetworkCount` -> 이벤트.

## 핵심 규칙과 이유
- **상호작용 타입(Interacting)**: `Interact()` 1회당 1 차감, 포션 대미지는 받지 않음. 이유: "손으로 따는" 채집물은 횟수가 곧 채집 가능 횟수라서입니다.
- **파괴 타입(Destroying)**: 상호작용으로 줄지 않고, 대상 종류가 맞는 포션 대미지 수치만큼만 차감. 이유: 나무, 광물은 맨손으로 못 부수고 채집 포션(서걱서걱, 깡깡)이 필요하다는 기획입니다.
- **남은 횟수는 `WorldObject`(컴포넌트)에 둠**: SO 는 같은 종류 오브젝트가 모두 공유하므로, SO 에 쓰면 꽃 하나를 따는 순간 모든 꽃이 줄어듭니다.
- **소진 이벤트는 한 번만**: `OnDepleted` 는 0 이 되는 순간 1회. 드롭 생성이 중복되지 않게 하기 위함입니다.
- **규칙은 `WorldObjectRules` 한 곳**: 혼자 할 때와 마스터 검증이 같은 함수를 써서, 두 경로의 규칙이 어긋나지 않습니다.
- **멀티 조건**: `NetworkId > 0` 이고 매니저가 있고 방에 들어와 있을 때(`UsesNetwork`). 요청은 마스터로 가고, 마스터가 검증 후 드롭을 **한 번만** 굴려 DropId 를 발급, 전원이 `ApplyNetworkCount` 로 적용. 클라이언트마다 굴리면 드롭 결과가 서로 달라지기 때문입니다.
- **사본 버전**: 적용마다 +1. `Ignored`(이미 반영) / `VersionGap`(놓침) / `Inconsistent`(어긋남)이면 반영하지 않고, `Ignored` 가 아니면 전체 목록을 다시 받습니다. 내 요청이 이 셋이면 제한 시간(기본 5초)을 기다리지 않고 즉시 `Fail(OutOfSync)` 로 끝냅니다.
- **`ResetCount` 는 로컬 전용**: 멀티에는 "횟수 되돌리기" 메시지가 없어, 방 안에서 부르면 마스터 사본과 어긋납니다. 그래서 경고만 하고 무시합니다.
- **`NetworkId` 0 = 로컬 전용**: 동기화 안 함. 번호는 씬 안 고유, 모든 클라이언트가 같은 값이어야 해서 씬에 저장합니다.

## 팀원이 쓰는 법 (코드 grep 으로 확인한 API)
| 이름 | 설명 |
| --- | --- |
| `bool Interact()` | 상호작용. 로컬: 차감되면 true. 멀티: **요청을 보냈으면 true**(실제 차감은 비동기) |
| `bool ReceivePotionDamage(WorldObjectDamagePotionEffect)` | 포션 대미지. 파괴 타입 + 대상 종류 일치 시만. 멀티는 **폭발 일으킨 클라이언트 1곳에서만** 호출 |
| `event Action<int,int> OnCountChanged` | (이전, 이후). 값이 바뀔 때만 |
| `event Action<WorldObject> OnDepleted` | 소진 시 1회 |
| `int remainingCount`, `bool isDepleted` | 읽기 전용 상태(`private set`) |
| `int NetworkId` | 0 이면 로컬. 인스펙터 `_networkId` 또는 메뉴 "Enzeun/월드 오브젝트/네트워크 번호 자동 부여" (Play 모드 불가, 실행 후 씬 저장) |
| `WorldObjectNetworkSyncManager.Register(WorldObject)` | 씬에 있던 것은 `Start` 에서 자동 등록. 런타임에 만든 것만 직접 호출 |
| `WorldObjectNetworkSyncManager.OnDropped` | `Action<WorldObject, WorldDrop[]>`. 전 클라이언트에서 같은 값으로 발생 |
| `WorldObjectNetworkSyncManager.IsActive` | 매니저 존재 && `PhotonNetwork.InRoom` |

## 호출 예시
```csharp
// 상호작용 (E 키)
if (worldObject.Interact()) { /* 로컬은 차감됨, 멀티는 요청 전송됨 */ }

// 소진 반응
worldObject.OnDepleted += wo => Debug.Log($"{wo.name} 소진");

// 드롭 받기 (멀티, 모든 클라이언트에서 호출됨)
WorldObjectNetworkSyncManager.Instance.OnDropped += (wo, drops) =>
{
    foreach (WorldDrop d in drops) { /* d.DropId, d.MaterialId, d.Count */ }
};

// 포션 폭발: 폭발을 일으킨 클라이언트에서만
worldObject.ReceivePotionDamage(effect);
```
`PotionEffectApplier` 가 `WorldObjectDamagePotionEffect` 를 받으면 `target.WorldObject.ReceivePotionDamage` 를 부릅니다.

## 하지 말아야 할 것
- 포션 대미지를 모든 클라이언트에서 호출 (요청이 N 번 가서 대미지 N 배). **코드로 막혀 있지 않고 호출하는 쪽이 지켜야 하는 약속입니다.**
- SO(`WorldObjectData`)에 남은 횟수 같은 런타임 값 쓰기.
- 멀티 중 `ResetCount()` 로 횟수 복구를 기대하기 (무시됨).
- 네트워크 번호를 겹치게 수동 입력 (등록 실패 경고, 그 오브젝트는 동기화 안 됨).
- `Interact()` 의 true 를 "이미 차감됨" 으로 믿기 (멀티는 전송 성공일 뿐).
- 클라이언트에서 `RollDrops` 를 직접 호출해 드롭 만들기 (마스터만 굴림).
- 기획 용어 혼용: 수치 이름은 "정신력"으로 통일.

## 아직 연결 안 된 것
- **드롭 줍기 동기화**: `MaterialItem` 은 `OnDropped` 에 아직 연결되지 않았습니다. `DropId` 는 다음 단계("누가 먼저 주웠나")를 위해 미리 발급합니다. 바닥 드롭은 스냅샷에도 없습니다.
- `WorldObjectDataManager`: 현재 사용처 없음. 재생성 등 나중을 위해 의도적으로 유지.
- 마스터가 나갈 때의 방폭 처리는 `NetworkFlowManager` 쪽(사용자 담당).
- Play 모드/멀티 실기 동작은 확인하지 못했습니다. (코드 읽기 기준)

## 용어집
| 용어 | 뜻 |
| --- | --- |
| Interacting / Destroying | 드롭 타입. 상호작용으로 줄어듦 / 포션 대미지로만 줄어듦 |
| 횟수 | `remainingCount`. 0 이 되면 소진 |
| 소진 | 횟수 0, `isDepleted`, 드롭 발생 |
| NetworkId | 씬 안 고유 번호. 0 = 로컬 전용 |
| 마스터 | 방장 클라이언트. 검증과 드롭 굴림 담당 |
| 사본 버전 | 적용마다 +1 되는 번호. 누락 감지용 |
| DropId | 마스터가 발급하는 드롭 고유 번호 |
| 대상 마스크 | `WorldObjectType` 값 번째 비트로 만든 종류 목록 (byte 하나) |
| 정신력 | 게임 내 수치 이름 (발표 자료의 "지능"과 같음, 코드/문서는 정신력) |
