## 코드 읽기 (9~10)

**Q9.** 아래 코드에서 수분이 0 일 때 결과 구간은? 두 `else if` 순서를 바꾸면 어떻게 되는가?
```csharp
if (hydration >= moistThreshold) currentHydrationState = HydrationState.Moist;
else if (hydration <= dehydratedThreshold) currentHydrationState = HydrationState.Dehydrated;
else if (hydration <= thirstyThreshold) currentHydrationState = HydrationState.Thirsty;
else currentHydrationState = HydrationState.Normal;
```

**Q10.** 정신력이 What(표: 멍청함 + 뭐라고?)에서 Confused(표: 멍청함 + 뭐라고? + 혼란)로 바뀌었다. 아래 `SyncEffects` 가 실제로 Remove / Apply 하는 효과는 각각 무엇이며, 멍청함의 타이머는 어떻게 되는가?
```csharp
removeBuffer.Clear();
CollectRemovedEffects(buffContainer.buffs, source, effects);
CollectRemovedEffects(buffContainer.debuffs, source, effects);
for (...) buffContainer.Remove(removeBuffer[i], source);
for (...)
    if (!IsAppliedBy(buffs, source, effects[i]) && !IsAppliedBy(debuffs, source, effects[i]))
        buffContainer.Apply(effects[i], source);
```

**Q9.** 결과는 **Dehydrated**. 순서를 바꾸면 0 도 `<=10` 을 만족해 **Thirsty** 가 되어 탈수 디버프가 영영 안 걸린다. 임계값이 포함 관계일 때는 더 좁은(심한) 조건을 먼저 둬야 한다는 점이 핵심.

**Q10.** Remove: 없음 (새 목록에 기존 멍청함, 뭐라고? 가 다 있음). Apply: 혼란(61003) 하나만. 멍청함의 타이머는 **유지된다**(다시 걸지 않으므로 초기화되지 않음). 전부 빼고 다시 걸면 주기 행동 타이머가 매번 리셋되는 문제가 생긴다. (`SurviveStatusManager.SyncEffects`)

**Q11.** 모범 답안: 구간 -> 효과는 기획이 자주 바꾸는 값이라 데이터로 분리했다. 게이지 매니저는 "값 -> 구간"만 책임져 단일 책임이 되고, 기획자가 SO 에서 효과를 추가/교체할 수 있다. 같은 구조를 4개 게이지가 공유(`StateEffects<TState>` 제네릭)해 중복도 줄었다. 단점은 표에 누락된 구간이 생기면 효과 없음(null)으로 조용히 넘어간다는 점이라, 데이터 검증이 필요하다. (`SurviveStatusEffectTable.Find`)

**Q12.** 모범 답안: 유지되는 효과를 다시 걸면 지속시간/주기 행동 타이머가 초기화되어 "구간 안에서 조금만 움직여도 타이머 리셋" 같은 버그가 생긴다. 차이만 반영하면 이를 막는다. source 를 게이지 매니저로 두면 체온 구간 변경이 수분이 건 효과나 포션이 건 효과를 건드리지 않고, 같은 효과라도 주체별로 독립 관리된다. 트레이드오프는 `IsAppliedBy`/`CollectRemovedEffects` 가 선형 탐색이라는 점인데, 효과 수가 적어 문제 없다.
